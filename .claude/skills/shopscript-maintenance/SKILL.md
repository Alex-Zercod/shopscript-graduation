# Работа с SHOPScript

Начни с README.md и docs/USER-GUIDE.md. Работай из корня проекта с server.py. Локальное приложение и публичный статический лендинг — разные части.

## Запуск

Нужны Python 3.10+ и локальная Ollama с входом, лимитом и доступом к модели из server.py. Пакеты Python не требуются. Запуск: `python -B server.py`, адрес http://127.0.0.1:8789/ . Windows-файл запуска вызывает start.py. Проверяй app_version через /api/status, а не только HTTP 200. После изменения правил перезапускай только проверенный процесс этого проекта. Не завершай посторонние процессы.

## Структура и правила

server.py — последовательные роли исследователя, планировщика, сценариста и редактора через одну модель Ollama; это не параллельные Agent-вызовы Claude Code. Не более одной доработки. public/ — форма, вывод, импорт и экспорт; examples/demo-brief.json — вымышленное задание.

Текущая схема каждого текста: Хук → Боль → Решение → Где купить. Цель — покупка показанного товара по прикреплённой ссылке, не просто переход и не сохранение названия. Заходы: direct сразу в проблему, friend разговорный юмор, topic интрига с быстрым раскрытием; не превращай topic в лекцию. Одна боль и решение допустимы в трёх вариантах, одинаковый ход рассказа — нет.

Сохраняй девять полей concept: id,title,hook,main_idea,development,climax,cta,filming,product_connection. main_idea — произносимая боль, development — решение, climax — раскрытие. Ответ помечен scheme=hook-pain-solution-link. Сохраняй десять полей script и четыре поля кадров. Сборка озвучки из кадров, таймкоды, длина, CTA и бюджет речи проверяются кодом. Хук до 7 слов и 2,3 слова/секунду — ориентиры, не измеренный хронометраж.

Не выдумывай опыт, свойства, цены, скидки, срочность и размещение ссылки. link_status — план автора прикрепить товар, не доказательство уже состоявшейся публикации. Не навязывай нанесение и до/после. Речь должна звучать естественно; технические указания — только в filming/visual. ready не означает одобрение заказчиком или подтверждённую эффективность. Качество автоматических текстов пока требует редакторской работы.

## Проверки

1. `python -m unittest discover -s tests -p test_server.py -v` — без облачных расходов.
2. `node --check public/app.js` при изменении JavaScript.
3. Облачные проверки запускай отдельно с учётом разрешённого расхода. tests/check_reviewer_live.py --live — лишь два учебных примера редактора, не полная приёмка.
4. Проверяй импорт, сохранность формы при ошибках, копирование, скачивание и выборочную доработку. Не выдавай вручную написанные примеры за результат модели.
5. Фиксируй реальные проверки и нерешённые замечания. Не запускай бесконечные попытки ради pass.

## Передача

Прочти docs/RELEASE-GUIDE.md. `python scripts/build_release.py` включает только явный список публичных файлов. Не публикуй личные ответы, фото, экспорты клиента, логи и секреты. Пакет не является публикацией. Проверяй состав ZIP и совпадение хешей. Публичный репозиторий и решение о публикации отзыва не создавай без пользовательского запроса.
